# 写作模式总表与 MODE.md 配置规格

> **本文件是整套流水线的「模式层」入口。** 本流水线原先只服务一种产物（6-8 万字的学位论文），
> 因此把「盲审质量」「GB/T 7714 顺序编码制」等**只对学位论文成立**的口径写进了角色与模板。
> 现在把这些口径全部提取为**模式参数**：先选模式，再由模式决定篇幅、结构单元、深度门槛、
> 引注体系、读者身份、审计口径与工作区台账粒度。
>
> **任何角色（planner / writer / auditor / librarian / consistency / blind-review / steward）
> 在执行任务前，都必须先读 `MODE.md`，以其中的参数覆盖本角色文件里的默认值。**

## 一、三个大模式

| # | 模式 id | 中文名 | 产物 | 默认结构单元 | 常见篇幅 | 默认引注体系 | 默认评审口径 |
|---|---|---|---|---|---|---|---|
| 1 | `degree-thesis` | 学位论文模式 | 毕业论文（本/硕/博） | 章 → 节 | 1.5 万 / 4 万 / 8 万+ 字 | 顺序编码制 `[n]` + GB/T 7714 | 盲审 / 答辩 |
| 2 | `journal-article` | 期刊论文模式 | 一篇投出去的稿子 | 全篇（引言→结论） | 6 千 – 1.2 万字 | **随目标期刊**（序号制或著者-年制） | 匿名外审 / 编辑初审 |
| 3 | `course-paper` | 课程论文模式 | 课程作业 | 题 → 论述段 | 2 千 – 8 千字 | 著者-年制（APA / Chicago）为主 | 任课教师评分 |

### 模式之间真正不同的地方

选模式不是换个称呼，它至少同时改变下面 8 件事——这也是为什么必须把它做成一级配置：

1. **结构单元与粒度**：学位论文按「章/节」推进并有目录约束；期刊论文是**单篇整体**（没有"下一节"可言，改稿以"版本"而非"章节"为单位）；课程论文按「题/论述段」推进，通常无目录。
2. **篇幅量级与分配逻辑**：学位论文要做全篇字数预算并防止章节失衡；期刊论文受**硬性字数上限**约束（超限直接退稿），必须做减法；课程论文按教师要求的区间，宁精勿滥。
3. **深度与创新性门槛**：博士要求理论/方法层面的原创贡献；硕士要求独立研究能力与一定新意；本科要求规范运用方法解决问题；期刊论文要求**可发表的边际贡献**（审稿人第一问"新在哪"）；课程论文只要求**正确运用课程理论**，不要求原创贡献。
4. **引注与著录体系**：学位论文中文语境默认顺序编码制 `[n]` + GB/T 7714；期刊论文**以目标期刊《投稿须知》为准**（不少社科期刊用著者-年制）；课程论文多为著者-年制。
5. **文献体量与时效**：博士/期刊综述要求文献覆盖度与前沿性（近 5 年占比）；课程论文文献量可少，但**必须真实可核验**。
6. **读者身份**：学位论文读者是盲审专家与答辩委员会；期刊论文读者是**匿名审稿人 + 编辑 + 同行**；课程论文读者是任课教师。
7. **审计口径**：auditor 的「学术规范」与第 5 维随模式改写（见第三节映射表）。
8. **台账粒度与状态机**：学位论文的 STATUS 表按章节列；期刊论文按**稿件版本**列（初稿/返修稿/终稿）+ 审稿意见应答表；课程论文按题列即可。

## 二、模式选择决策树

```
用户要写的是什么？
│
├─ 交给学校/学院评审、有学位授予含义？
│   └─▶ 模式 1：degree-thesis
│         └─ level：本科 bachelor / 硕士 master / 博士 doctor
│
├─ 要投给期刊、有审稿流程？
│   └─▶ 模式 2：journal-article
│         └─ 必须先确认：目标期刊 + 期刊层级 + 稿件类型 + 字数上限 + 引注体例
│
└─ 交给老师、算课程成绩？
    └─▶ 模式 3：course-paper
          └─ 必须先确认：课程名 + 教师要求（篇幅/引注/提交格式）+ 评分点
```

**判不准时怎么办**：向用户提一个二选一问题（"这份是要交学校评审的，还是投期刊/交课程的？"），
**不得擅自默认**。同一用户可能同时有多个模式的需求——此时**每个项目根各用一份 MODE.md**，
不要在一个工作区里混着写。

## 三、MODE.md 配置规格（唯一口径来源）

部署时（或首次会话时）在**项目根目录**生成 `MODE.md`（模板见 `templates/MODE.md`）。
**所有角色读它，而不是读模式的通用文档**——通用文档解释"为什么"，MODE.md 规定"这一篇具体怎么办"。

### 必填字段

| 字段 | 取值 | 说明 |
|---|---|---|
| `mode` | `degree-thesis` \| `journal-article` \| `course-paper` | 三个大模式之一 |
| `level` | `bachelor` \| `master` \| `doctor` \| `n/a` | 仅 degree-thesis 用；其余填 `n/a` |
| `discipline` | 任意学科名（如 教育学 / 计算机科学 / 材料科学 / 社会学） | **不预设学科**；决定术语体系与文献分布 |
| `language` | `zh` \| `en` \| 其他 | 写作语言 |
| `target_length` | 字数区间 | journal-article 必须是期刊**硬上限** |
| `structure_unit` | `节` \| `全篇` \| `题` | 每次写作任务推进的单位 |
| `citation_style` | `numeric` \| `author-date` \| `footnote` | 与 `citation_standard` 配套 |
| `citation_standard` | 如 `GB/T 7714—2015` \| `APA 7th` \| `Chicago 17th` \| `<目标期刊体例>` | 著录格式 |
| `review_gate` | `盲审` \| `匿名外审` \| `课程评分` \| `仅自查` | 决定 auditor 第 5 维口径 |
| `audience` | 读者身份 | 如"盲审专家与答辩委员会" |

### 条件必填字段

| 字段 | 何时必填 | 说明 |
|---|---|---|
| `target_journal` | journal-article | 目标期刊名 |
| `journal_tier` | journal-article | 如 CSSCI / SSCI Q1 / 北大核心 / 普刊 |
| `article_type` | journal-article | `原创研究` \| `综述` \| `案例` \| `方法` \| `书评` |
| `word_limit_hard` | journal-article | 硬上限（含摘要参考文献的口径需注明） |
| `course_name` / `instructor_requirements` | course-paper | 课程名与教师要求原文 |
| `grading_rubric` | course-paper | 评分点清单（有则逐条对齐） |
| `school_format` | degree-thesis | 学校学位论文格式规范文件名/链接（如有） |

### 从模式推导的默认值（不必手填，角色按此推导）

| 参数 | degree-thesis | journal-article | course-paper |
|---|---|---|---|
| 审计维度重心 | 盲审五维（含创新性梯度） | 匿名外审口径 + **期刊适配** | 课程评分点 + 理论运用正确性 |
| 创新性要求 | 按 level 梯度（见模式 1 文档） | 可发表的边际贡献 | 不要求原创，要求正确运用 |
| 文献覆盖面 | 全而深，近 5 年占比有要求 | 精而准，直指研究缺口 | 够用即可，但必须真实 |
| 结构刚性 | 高（受目录/编号约束） | 中（受期刊模板约束） | 低 |
| STATUS 台账粒度 | 章/节 + 四态 | **稿件版本** + 审稿意见应答 | 题目清单 |
| 是否需目录同步 | 必须（改标题须同步目录） | 不需要 | 不需要 |
| 评审预审角色 | 常规按需触发 | 改为**模拟审稿人预审** | 通常不必跑 |

### MODE.md 示例（学位论文 · 硕士）

```markdown
# MODE.md — 本项目写作模式配置

- mode: degree-thesis
- level: master
- discipline: 教育技术学
- language: zh
- target_length: 40000-50000 字
- structure_unit: 节
- citation_style: numeric
- citation_standard: GB/T 7714—2015（学校格式规范另有要求时以学校为准）
- review_gate: 盲审
- audience: 盲审专家与答辩委员会
- school_format: <学校研究生院学位论文格式规范.pdf>
```

### MODE.md 示例（期刊论文）

```markdown
# MODE.md — 本项目写作模式配置

- mode: journal-article
- level: n/a
- discipline: 计算机科学
- language: zh
- target_journal: 《计算机学报》
- journal_tier: 中文一级学报
- article_type: 原创研究
- word_limit_hard: 12000 字（含图表摘要，参考文献不计）
- target_length: 9000-11000 字
- structure_unit: 全篇
- citation_style: numeric
- citation_standard: 目标期刊《投稿须知》体例
- review_gate: 匿名外审
- audience: 匿名审稿人与责任编辑
```

## 四、模式如何改变各角色的行为（映射表）

| 角色 | degree-thesis | journal-article | course-paper |
|---|---|---|---|
| **planner** | 规划"某一节"，咬合全篇论点线 | 规划**整篇骨架**：研究缺口→贡献→证据链→结论 | 规划题面→论述段落→课程理论落点 |
| **writer** | 按节成文，达盲审质量 | 按期刊体例成文，**严守字数上限**，摘要/关键词/图表齐备 | 按论述段成文，突出与课程理论的咬合 |
| **auditor** | 五维：学术规范/逻辑/文献/**盲审标准**/语言机器感 | 五维：学术规范/逻辑/文献/**审稿人口径（含期刊适配与字数合规）**/语言机器感 | 五维：学术规范/逻辑/文献/**课程评分点**/语言机器感 |
| **blind-review** | 模拟盲审，滚动预审 | 模拟**匿名审稿人**，按"新在哪/证据够不够/能不能发"提问 | 模拟**任课教师**，按评分点提问 |
| **consistency** | 术语译名/概念定义/论点口径/**章节编号** | 术语译名/概念定义/论点口径/**全篇术语与摘要-正文-结论三处口径一致** | 术语译名/概念定义/论点口径 |
| **librarian** | 全量落库，按主题归子集合 | 全量落库 + **标注该文献对"研究缺口"的具体作用** | 落库从简，但**真实性标准不降** |
| **steward** | 四态章节清单 + 目录同步 + 防编号错乱 | **稿件版本台账** + 审稿意见应答表 + 字数实时核对 | 题目清单 + 进度 |

## 五、三个模式共享的不变量（与模式无关，任何情况都不得放松）

无论哪种模式，以下规则**一律不变**——这是本流水线的底线：

1. **规划未经用户确认不得动笔**（硬闸门）；
2. **正文未经独立审计不得交付**（硬闸门）；
3. **文献必须真实可核验，不得臆造**；PDF 优先正规渠道，灰色站点链接绝不写入正文或参考文献；
4. **无摘要不引文**——不得凭题名臆测文献观点；
5. **术语与概念口径全文统一**，以 glossary.md 为准；
6. **引用与文末参考文献、文献库条目一一对应**（三对照）；
7. **规划者、写作者、审计者必须是不同角色**，避免自写自审的同温层。

> 模式决定的是**"达到什么标准"**，不是**"要不要走流程"**。课程论文同样要过规划确认与独立审计，
> 只是审计的靶子从"盲审质量"换成"课程评分点"。
