# 文献库分类集合设计（示例）

文献库按「父集合 → 主题子集合」两级组织。所有写作相关条目必须**当场归入**对应主题子集合，严禁散落在文库根部；跨主题文献可同时归入多个子集合。

## 集合结构示例（以虚构课题《城市社区居家养老服务供需匹配机制研究》为例）

```
研究文献库（父集合，键由用户提供）
├── 理论基础与福利多元主义
├── 养老服务政策与制度
├── 多主体供给与治理
├── 老年人需求与行为
├── 实证方法与统计数据
└── 国际比较与前沿（按需）
```

> 替换课题时，把子集合改为对应课题的主题域即可，结构保持"父集合 → 主题子集合"两级。

## 落库规则

1. **用到一篇、落一篇**，不攒批、不遗漏、不重复（入库前先按标题/DOI 查重）；
2. 完整元数据：标题、作者、年份、期刊、卷期页码、DOI；能附 PDF 就 attach；
3. 统一打上与论文相关的标签（如课题关键词）；
4. 每次批量入库后**回读核对**（count 各集合条目数），确认无误再汇报；
5. 正文引用与文献库条目一一对应——引用某条时记录其条目 id，防失配。

## PDF 获取渠道（只走合规渠道）

- ✅ 期刊官网 / 作者个人主页 / DOI 直链 / 机构数据库（如校园网内网）；
- ❌ **禁止使用或引导使用任何侵权盗版站点**（含各类灰色文献下载站），也绝不把此类站点写入正文或参考文献；
- ⚠️ 确实拿不到 → 如实注明"暂无 PDF，待图书馆/馆际互借补"，不虚报。

## 元数据补全

卷期页码能查到就补全（查 Crossref / 出版社官网 / 图书馆目录）；查不到的如实注明"（卷期/页码待核验）"，**绝不凭空杜撰**——宁可标注待核验，不可编造。
