# 跨会话恢复协议（Session Recovery Protocol）

> 长文写作必然跨几十次会话完成（学位论文的 6-8 万字尤其如此；期刊论文与课程论文会话数较少，
> 但同样需要恢复）。本协议保证：**任何新会话在 5 分钟内恢复到与上次完全一致的状态**——
> 知道写到哪、口径是什么、标准是什么、下一步做什么。
>
> 主代理每次收到写作指令、执行第〇步（同步进度）前，先按本协议恢复上下文。

## 为什么需要

主代理会话有上下文窗口限制，长文写作会不断开新会话。没有本协议，每次新会话都会：
"失忆"（不知道写过什么）、"漂移"（术语口径跑偏）、"**降标准**"（忘了本项目是哪个模式，
用错标准）、"返工"（重复已写章节）。

四个工件 + 一个动作解决：**MODE.md（模式与标准）**、STATUS.md（进度台账）、
glossary.md（口径基准）、session-handoff.md（交接卡），外加"先恢复再动手"的固定动作。

> **MODE.md 必须最先读**：它是本项目一切标准的来源（篇幅、结构单元、引注体系、评审口径、
> 台账粒度）。漏读它会导致"用学位论文的标准写课程论文"之类的系统性偏差。

## 工作区固定结构（约定，模板在 templates/）

```
项目根/
├── MODE.md                # 【最先读】写作模式配置（mode/level/字数标准/引注体系/评审口径）
├── STATUS.md              # 进度台账（steward 维护，每次任务前后更新；粒度随模式）
├── glossary.md            # 术语与概念口径基准（consistency 的锚）
├── session-handoff.md     # 上次会话交接卡（steward 每次会话结束前更新）
├── <稿件>.docx            # 正文主文件（Word 主文件）
├── _进度_最新.md           # docx 转换快照（docx2md.ps1 产物，供主代理阅读）
├── _文献池_最新.md         # 检索到的文献完整条目（含摘要，planner 落盘）
└── <章节/稿件>.md          # 已交付正文（学位论文建议一节一文件；期刊论文按版本命名）
```

**台账粒度随 `MODE.md` 的 `mode` 而变**：

| mode | STATUS.md 粒度 | 是否需目录同步 | 特有工件 |
|---|---|---|---|
| `degree-thesis` | 章节四态清单 + 字数预算偏差 | **需要** | 大纲.md、字数预算表 |
| `journal-article` | **稿件版本台账** + 审稿应答进度 | 不需要 | 审稿意见应答表 |
| `course-paper` | 题目/段落清单 | 不需要 | 课程要求对照表 |

## 恢复流程（新会话启动时，steward 执行）

```
第 0 步  读 MODE.md
        └─ 知道：本项目是哪个模式/档位，字数标准、引注体系、评审口径分别是什么
第 1 步  读 STATUS.md
        └─ 知道：哪些结构单元已写/已审/待写，当前进行到哪
第 2 步  读 glossary.md
        └─ 知道：术语译名与概念定义口径（防漂移的锚）
第 3 步  读 session-handoff.md
        └─ 知道：上次进行到哪、下一步动作、遗留问题、口径备忘
第 4 步  若用户粘贴了正文 / docx 有更新 → 跑第〇步 docx2md 刷新快照并通读
        └─ 知道：最新正文实际状态（以对话粘贴为准、以 docx 校对）
第 5 步  steward 向主代理汇报"当前状态 + 模式 + 下一步建议" → 开始本次任务
```

> 汇报时**必须带上模式**（例如"当前项目：期刊论文模式，v3 返修稿，11200/12000 字"）——
> 这样用户能在第一时间发现模式配错。

## 触发时机

| 时机 | 动作 |
|---|---|
| 新会话第一条写作指令前 | 执行上述第 0-3 步（快照在第〇步做） |
| 每次写作任务前后 | steward 更新 STATUS.md |
| 每次会话结束前 | steward 填写 session-handoff.md（2 分钟） |
| 首次定义新术语/概念时 | 立即登记进 glossary.md |
| **模式或档位变更时** | 立即更新 MODE.md，并同步 STATUS.md 的表头与台账形态 |

## 防漂移要点

- consistency 每次审查都以 glossary.md 为基准，**而不是凭记忆**；
- **一切标准以 MODE.md 为准**——不得凭"上次好像是这么写的"推断标准；
- **学位论文模式**：章节标题改动必须同步到 STATUS.md 与论文目录（大纲），不得只改正文；
- **期刊论文模式**：改稿以版本为单位，每次修订另存新版本并登记字数，**不要覆盖旧版本**
  （审稿人可能要求对比修改前后）；
- 若用户明确推翻某概念定义，先改 glossary.md，再改稿件正文，防止半途口径分裂；
- handoff 卡的"口径备忘"栏是给下次会话的警告牌——上次踩过的坑要写在上面。

## 与主提示词的衔接

主提示词「第〇步：写作前读模式配置 + 同步稿件进度」之后、进入独立规划之前，应执行本协议的
恢复流程。可将本协议路径写入 system-prompt.md 的"工作区结构"说明，或直接让 steward 角色
（见 prompts/roles/steward.md）在每次任务开始时执行本协议。
