# 跨会话恢复协议（Session Recovery Protocol）

> 6-8 万字的学位论文必然跨几十次会话完成。本协议保证：**任何新会话在 5 分钟内恢复
> 到与上次完全一致的状态**——知道写到哪、口径是什么、下一步做什么。主代理每次收到写作指令
> 时执行第〇步（同步进度）前，先按本协议恢复上下文。

## 为什么需要

主代理会话有上下文窗口限制，长文写作会不断开新会话。没有本协议，每次新会话都会：
"失忆"（不知道写过什么）、"漂移"（术语口径跑偏）、"返工"（重复已写章节）。
三个工件 + 一个动作解决：STATUS.md（进度台账）、glossary.md（口径基准）、
session-handoff.md（交接卡），外加"先恢复再动手"的固定动作。

## 工作区固定结构（约定，模板在 templates/）

```
项目根/
├── STATUS.md              # 进度台账（steward 维护，每次任务前后更新）
├── glossary.md            # 术语与概念口径基准（consistency 的锚）
├── session-handoff.md     # 上次会话交接卡（steward 每次会话结束前更新）
├── <论文>.docx            # 论文正文（Word 主文件）
├── _论文进度_最新.md       # docx 转换快照（docx2md.ps1 产物，供主代理阅读）
└── <章节>.md / <章节>_修订稿.md   # 各章已交付正文（建议一人一文件）
```

## 恢复流程（新会话启动时，steward 执行）

```
第 1 步  读 STATUS.md
        └─ 知道：哪些章节已写/已审/待写，当前进行到哪
第 2 步  读 glossary.md
        └─ 知道：术语译名与概念定义口径（防漂移的锚）
第 3 步  读 session-handoff.md
        └─ 知道：上次进行到哪、下一步动作、遗留问题、口径备忘
第 4 步  若用户粘贴了正文 / docx 有更新 → 跑第〇步 docx2md 刷新快照并通读
        └─ 知道：最新正文实际状态（以对话粘贴为准、以 docx 校对）
第 5 步  steward 向主代理汇报"当前状态 + 下一步建议" → 开始本次任务
```

## 触发时机

| 时机 | 动作 |
|---|---|
| 新会话第一条写作指令前 | 执行上述第 1-3 步（快照在第〇步做） |
| 每次写作任务前后 | steward 更新 STATUS.md |
| 每次会话结束前 | steward 填写 session-handoff.md（2 分钟） |
| 首次定义新术语/概念时 | 立即登记进 glossary.md |

## 防漂移要点

- consistency 每次审查都以 glossary.md 为基准，**而不是凭记忆**；
- 章节标题改动必须同步到 STATUS.md 与论文目录（大纲），不得只改正文；
- 若用户明确推翻某概念定义，先改 glossary.md，再改论文正文，防止半途口径分裂；
- handoff 卡的"口径备忘"栏是给下次会话的警告牌——上次踩过的坑要写在上面。

## 与主提示词的衔接

主提示词「第〇步：写作前同步论文进度」之后、进入独立规划之前，应执行本协议的恢复流程。
可将本协议路径写入 system-prompt.md 的"工作区结构"说明，或直接让 steward 角色
（见 prompts/roles/steward.md）在每次任务开始时执行本协议。
