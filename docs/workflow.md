# 全流程工作协议（第〇步～第五步）

写作任务一律按以下流水线执行，**不得跳过任何一步**。质量不靠主代理的"自觉"，靠流程结构上的硬闸门：规划未经用户确认不得动笔，正文未经独立审计不得交付。

> **模式先行**：本协议**不预设论文类型**。开工前先读项目根目录 `MODE.md`
> （模板 `templates/MODE.md`，规格 `modes/_mode-overview.md`），由模式决定篇幅标准、结构单元、
> 深度门槛、引注体系、评审口径与台账粒度。三个模式共享同一条流水线，
> **只有"达到什么标准"随模式而变**（见第五节模式差异对照）。

## 流水线总览

```
第〇步 读 MODE.md（模式配置）＋ 状态恢复（STATUS/glossary/handoff/LEDGER）＋ 同步进度（docx2md 快照）
   ↓
第〇·五步【仅实证单元】数据可得性闸门（A/B/C/D）＋ 数据台账 ＋ 分析结果落盘（analyst）
   ↓
第一步 独立规划（planner）──▶ 用户确认（硬性闸门，未确认不进入写作）
   ↓
第二步 执行写作（writer，严格按已确认规划）
   ↓
第三步 独立审计（auditor）──▶ 通过？── 否 ──▶ 退回 writer 修订，循环
   │ 通过
   ▼
   ├─ 术语与一致性审查（consistency，含第 5 维「测量与数据一致性」）
   ├─ 评审预审（blind-review，按模式模拟盲审专家/匿名审稿人/任课教师）
   ▼
第四步 文献落库（librarian，用到一篇落一篇）＋ 数据与结果留痕
   ↓
第五步 交付（引注三对照 + 篇幅核验 + 摘要与图表编号核验 + DOI 有效性）
```

> **改写任务不走"从零"路径**：若本次是**改写已有章节**而非新写，须先按
> [`docs/rewrite-protocol.md`](rewrite-protocol.md) 跑依赖传播，得出影响清单再逐节处理；
> 等级 1（须重写论证）的节必须重跑 planner 与用户确认，**不得让 writer 直接改**。

## 第〇步：写作前读模式配置 + 同步稿件进度

主代理无法直接阅读 .docx（二进制压缩包）。收到写作指令、进入独立规划前必须按序完成：

1. **读 `MODE.md`**（最先做，缺则先补）：确认 `mode` / `level` / 字数标准 / 引注体系 / 评审口径，
   以及 `has_empirical`（是否含实证单元）。**MODE.md 不存在时，按 `templates/MODE.md` 生成并请
   用户确认后再继续**——模式未定不得开工；
2. **恢复跨会话状态**（见 `docs/session-recovery.md`：读 STATUS.md → glossary.md → session-handoff.md，
   并跑 `scripts/ledger-impact.ps1` 自检依赖台账）；
3. **docx → markdown 转换**并通读最新进度（粒度随模式：章节 / 全篇版本 / 题目）。

**转换命令**（PowerShell，工作目录 = 项目目录）：

```powershell
# 推荐：调用仓库脚本（自动定位 docx、同名取最新、处理占用）
powershell -ExecutionPolicy Bypass -File scripts/docx2md.ps1 -DocxPath "稿件文件.docx"

# 备选：手工模板
Add-Type -AssemblyName System.IO.Compression.FileSystem
$zip = [System.IO.Compression.ZipFile]::OpenRead("<稿件文件.docx>")
$e = $zip.Entries | Where-Object { $_.FullName -eq "word/document.xml" }
$r = New-Object System.IO.StreamReader($e.Open()); $xml = $r.ReadToEnd(); $r.Close(); $zip.Dispose()
$xml = $xml -replace '</w:p>', "`n" -replace '<[^>]+>', ''
$xml = $xml -replace '&amp;','&' -replace '&lt;','<' -replace '&gt;','>' -replace '&quot;','"' -replace '&apos;',"'"
Set-Content -Path "_进度_最新.md" -Value $xml -Encoding UTF8
```

要点：

- 同名文件可能存在于多个目录时，取 LastWriteTime 更新的那份（docx2md.ps1 已内置该逻辑）；
- 文件被 Word/OneDrive 锁定（PermissionError）时，改从可读副本提取；
- 转换后必须通读快照：哪些结构单元已写、哪些待写、标题编号有无变动；
- 以对话粘贴为准、以 docx 校对，避免两头不一致；
- 转换失败则如实说明，请用户粘贴相关文本替代；
- 进度与结构状态由 steward 维护（写入 STATUS.md，**粒度随模式**）；术语口径以 glossary.md 为基准；
  会话结束前 steward 填写 session-handoff.md（模板均在 templates/）。

## 第〇·五步：数据可得性闸门（仅含实证单元的稿件）

**此前的缺口**：流水线只覆盖「文献 → 论证 → 写作」，但含实证部分的稿件，*结果*一章的输入是
**数据与分析**。缺这一环会导致三类事故：写不出来、**硬编数据**、口径互斥。

**主代理在规划任何含实证内容的结构单元之前，必须先跑本步骤：**

1. 判定数据可得性状态（写入 `DATA.md` 第一节）：

   | 状态 | 含义 | 允许的动作 | 禁止 |
   |---|---|---|---|
   | `A` | 数据与分析结果均已有 | 正常进入规划 | — |
   | `B` | 数据已有，分析未做 | 先由 analyst 分析并落盘，**再**规划 | ❌ 不得"先写大概，数字后补" |
   | `C` | 数据未采集完 | 只写研究设计/方法章 | ❌ 不得写结果章数值（仅可 `<待填>` 骨架） |
   | `D` | 无实证数据（纯理论/思辨型） | 全局跳过本步骤 | ❌ 不得虚构数据凑"实证"外观 |

2. 经 subagent_role 委派 **analyst**：核验/执行分析 → 把完整结果（系数/标准误/CI/显著性/N/
   拟合指标 + 软件版本 + 对应图表编号）落盘 `_分析结果_最新.md`（模板 `templates/results.md`）；
3. 登记变量与测量口径（`DATA.md` 第三节）、数据处理留痕（第四节）、图表规格（第六节）；
4. 登记未能完成的分析（放 `_分析结果_最新.md` 末节）——**如实登记缺口比补一个假数字安全得多**。

**硬性红线**：正文出现的任何数据必须能追溯到 `_分析结果_最新.md` 或作者提供的原始输出。
**无法追溯的数字一律视为编造**——与"文献不得臆造"同级。

> writer 拿不到结果条目时**不得写入任何数值**，须回报主代理索要；委派 writer/auditor 时
> 必须让其读到 `_分析结果_最新.md` 或完整内联结果条目（**严禁只给结论式摘要**）。
> 完整规格见 [`docs/data-pipeline.md`](data-pipeline.md)。

## 第一步：写作前独立规划

经 subagent_role 委派 planner（独立子代理，不共享写作语境，保持视角中立），
**委派时须指明 `MODE.md` 路径**：

1. 任务解析：本次结构单元的核心论点、论证任务、在整体结构中的位置、**篇幅配额**；
2. 中外文献检索（中文库一次一关键词；外文库；必要时 web 补充前沿）——对每篇候选文献取回
   **完整条目并落盘** `_文献池_最新.md`（完整摘要+全部元数据，不截断；接口未提供字段才注明
   "接口未提供"）；
3. **文献传递协议**：委派 planner/writer/auditor 时必须让其读到含摘要的完整条目
   （首选读 `_文献池_最新.md`，否则内联）；**严禁只传"作者+题名+出处"精简清单**——
   writer 无摘要不得引文，auditor 以摘要核对观点归属；
4. 产出写作规划报告：核心问题与论证目标 / 段落结构（细化到分论点+篇幅分配）/
   拟引文献清单及**每篇的具体用途（依摘要判定）** / 与稿件底层画像的咬合点 /
   写作难点与需作者补充的信息；
5. **暂停，交用户确认**；收到修改意见则修订后再呈报，直至确认通过。

**篇幅分配按模式**：

| 模式 | 规划粒度 | 篇幅纪律 |
|---|---|---|
| degree-thesis | 某一节 | 整篇先出字数预算表（主体分析章须占 45-55%） |
| journal-article | 整篇骨架（或某一章节） | 从**硬上限**反推，留 5% 余量；开工前须确认目标期刊/类型/上限/体例 |
| course-paper | 某一题 | 取要求区间**中下位**，宁短勿长 |

## 第二步：按确认结果执行写作

经 subagent_role 委派 writer，**委派时须指明 `MODE.md` 路径**：

- 严格按已确认规划执行，沿用规划阶段已确认文献；
- 新增检索与使用的文献同样纳入落库流程；
- 正文引注按 `MODE.md` 的引注体系标注（`numeric` → `[n]`；`author-date` → `（作者, 年份）`；
  `footnote` → 页下注）；
- **篇幅遵守配额**：期刊模式接近硬上限时主动压缩而非继续扩写；
- 主代理只做统筹（提供上下文、衔接前文、汇总交付），**不自行撰写正文**。

## 第三步：写作完成后的独立审计

经 subagent_role 委派 auditor（冷眼旁观、挑毛病立场）做五维审计，**第 4 维随模式改写**：

1. 学术规范（概念准确、论证严密、无空洞套话）；
2. 逻辑结构（段落衔接、章节过渡、咬合规划与稿件结构）；
3. 文献（真实存在、格式合规、融入行文、引注与文末对应）；
4. **评审口径（随模式）**：
   - `degree-thesis` → 盲审标准（该档位语言/篇幅/创新性门槛）；
   - `journal-article` → 审稿人口径（贡献可辨识、证据支撑、**期刊体例与字数上限合规**）；
   - `course-paper` → 课程评分点（逐条对齐教师要求；**不得以创新性不足退回**）；
5. 语言机器感 / AI 味（只报高密度与空转，学科文风豁免，只报告不改写）。

审计结论为「通过」或「需修订（附具体意见）」；需修订则退回 writer 修改 → 再送审，循环至通过。

审计通过后、交付前另有两道滚动把关：

- **consistency（术语与一致性）**：以项目根目录 glossary.md 为基准，与此前所有已写内容做口径比对
  （术语译名、概念定义、论点口径），输出差异清单，冲突退回 writer 修正后复检；首次定义的新术语
  须登记进 glossary.md。**模式附加项**：学位论文核对章节编号与标题同步；
  期刊论文核对摘要—正文—结论三处贡献表述一致；课程论文核对理论口径与课程所授一致；
- **blind-review（评审预审，按需）**：按模式模拟评审者——学位论文模拟**盲审专家**并对本节及此前
  全部章节做滚动预审（空洞套话、论证跳步、章节失衡、跨章断裂、术语误用）；
  期刊论文模拟**匿名审稿人**；课程论文模拟**任课教师**（通常只跑一次）。
  按严重度输出问题清单，重大问题退回修正。

## 第四步：文献落库

经 subagent_role 委派 librarian：用到一篇落一篇；完整元数据 + 可附 PDF；**PDF 优先走正规渠道**
（期刊官网/作者主页/DOI/机构数据库），正规渠道无法获取时 z-library / sci-hub 可作最后通道
（著录一律走正规刊源，灰站链接绝不写入正文或参考文献）；按主题归入文献库子集合、打标签；
批量入库后回读核对条目数。详见 `docs/zotero-schema.md`。

## 第五步：引用与参考文献格式规范

**引注体系由 `MODE.md` 决定，不得一律套用同一套体例**：

| `citation_style` | 正文形态 | 文末排列 | 核验方式 |
|---|---|---|---|
| `numeric` | `[n]` 上标，按首次出现顺序编号 | `citation_standard`（中文学位论文默认 GB/T 7714—2015） | `citation-check.ps1 -Style numbered` |
| `author-date` | `（作者, 年份）` / `(Author, Year)` | 按作者姓氏字母序，不编号 | `citation-check.ps1 -Style author-date` |
| `footnote` | 页下脚注 | 文末另附参考文献 | 人工逐条核验（脚本不支持） |

通用规则：

- 编号制下：编号按首次出现顺序，重复引用沿用原编号；引用处必须直接标注，不得用作者名引注代替；
- 卷期页码能查就补全，查不到注明"（卷期/页码待核验）"，**不得杜撰**；
- 外文人名与术语译名全文统一，不得混用（以 glossary.md 为准）；
- 每条参考文献都能在文献库找到对应条目，引注与文末一一对应；
- **交付前跑引用三对照**：
  `powershell -ExecutionPolicy Bypass -File scripts/citation-check.ps1 -TextPath <文件.md> -Style <numbered|author-date>`
  完成机械核对（正文 ⇄ 文末），再人工对照文献库（核对单模板 `templates/citation-audit.md`）。

## 篇幅核验（三模式均须做，口径不同）

**字数必须机械核验，不得靠模型自估**——模型不会真的计数，而三个模式的篇幅纪律都依赖它。

```powershell
# 期刊论文模式：硬上限（超限在编辑初审即被拦）
powershell -ExecutionPolicy Bypass -File scripts/word-count.ps1 -TextPath "稿件_v3.md" -Limit 12000 -ExcludeRef

# 课程论文模式：区间（超上限不加分，低于下限扣分）
powershell -ExecutionPolicy Bypass -File scripts/word-count.ps1 -TextPath "课程论文.md" -Min 3000 -Max 5000 -ExcludeRef

# 学位论文模式：逐章统计，与字数预算表比对
powershell -ExecutionPolicy Bypass -File scripts/word-count.ps1 -TextPath "." -Pattern "第*章*.md" -ExcludeRef
```

| 模式 | 参数 | 判定 |
|---|---|---|
| degree-thesis | 不给配额，逐章统计后与预算表比对 | 累计偏差 >20% 须上报用户 |
| journal-article | `-Limit <word_limit_hard>` | 超限即"需修订"；占用 ≥95% 给预警（返修最易超限） |
| course-paper | `-Min -Max <区间>` | 超出区间即不合格；规划时取中下位 |

> 注：`-ExcludeRef` 对应"参考文献不计"的常见口径；是否含摘要/图表题注以目标刊或学校的规定为准。
> 脚本为机械口径，与对方系统的统计可能略有差异，**以对方系统为准**。

## 各模式的差异对照（同一条流水线，不同的标准）

| 环节 | degree-thesis | journal-article | course-paper |
|---|---|---|---|
| 第〇步 进度粒度 | 章/节 | 稿件版本 | 题目/段落 |
| 第一步 规划粒度 | 某一节 + 全篇字数预算 | 整篇骨架，从硬上限反推 | 某一题，区间中下位 |
| 第一步 额外前置 | 大纲/目录就位 | **确认期刊/类型/上限/体例**（缺则不开工） | **确认课程要求与评分点** |
| 第三步 第 4 维 | 盲审标准 | 审稿人口径（含期刊适配） | 课程评分点 |
| 第三步 预审角色 | 盲审专家（滚动） | 匿名审稿人 | 任课教师（一次） |
| 第四步 文献要求 | 覆盖面+近 5 年占比 | 精而准，直指研究缺口 | 够用即可，真实性不降 |
| 第五步 引注默认 | `[n]` + GB/T 7714 | 随目标期刊 | 著者-年制 |
| 特有工件 | 字数预算表、目录同步、编号防错 | 版本台账、审稿意见应答表、投稿信 | 课程要求对照自查表 |
| 不需要的工件 | 投稿信、审稿应答 | 目录同步、编号防错 | 目录同步、编号防错、滚动盲审 |
