# 实证数据环节（Data Pipeline）

> **为什么需要本文件**：本流水线原先只覆盖「文献 → 论证 → 写作」。但若稿件含实证部分，
> *结果*一章的输入是**数据与分析**，而非文献——此前这一环完全缺席，导致三类事故：
>
> 1. **写不出来**：作者说"帮我写第四章结果"，但结果取决于还没跑的回归；
> 2. **硬编数据**：writer 为了交差编造"β=0.42, p<0.01"——这是学术不端，且比编造文献更难被发现；
> 3. **口径互斥**：变量的测量口径散落在各章，表 3 说"三科加权"、正文说"平均分"。
>
> 本文件补齐这一环：**数据可得性闸门**（答"能不能写"）→ **数据台账**（答"基于什么写"）
> → **分析结果落盘**（答"数字从哪来"）→ **测量口径校验**（防互斥）→ **图表规格**（供图表检查）。
>
> 流程上的位置：插在**第〇步（状态恢复）之后、第一步（规划）之前**。

## 适用范围

| 模式 | 是否需要实证数据环节 |
|---|---|
| `degree-thesis` | **视研究设计而定**——实证/量化/实验类必须走；纯理论/思想史/文本考据类可整节跳过 |
| `journal-article` | **视 `article_type` 而定**——`原创研究`/`案例`/`方法` 必须走；`综述`/`书评` 可跳过 |
| `course-paper` | 视课程要求而定；理论研讨课通常跳过，方法课/实验课必须走 |

**判断方式**：稿件是否存在"结果"性质的章节（结果/实证/分析/实验/案例发现）。
存在即必须走本环节。**不得因"麻烦"而跳过**——跳过等于默许编造数据。

---

## 一、数据可得性闸门（最重要的新增闸门）

在规划任何含实证内容的结构单元之前，主代理**必须先问清数据处于哪种状态**，
并按状态选择动作。**这是硬闸门：状态未明不得进入规划。**

| 状态 | 判定 | 允许的动作 | 禁止的动作 |
|---|---|---|---|
| **A. 数据与分析结果均已有** | 作者能提供数据文件或已有的统计输出 | 进入规划 → analyst 核验并落盘 → writer 写结果章 | — |
| **B. 数据已有，分析未做** | 有数据文件，但未跑分析 | 先由 analyst 执行/指导分析，结果落盘，**再**进入规划 | ❌ 不得"先写个大概，数字后补" |
| **C. 数据未采集完** | 数据在收集中 | 只写**分析框架/研究设计/方法**章（不涉结果） | ❌ 不得写结果章，哪怕是占位 |
| **D. 数据不存在且不打算采集** | 纯文献/理论/思辨型研究 | 全局跳过本环节；章节改为论证型写法 | ❌ 不得虚构数据以凑"实证"外观 |

### 状态 C / D 的产出约定（防止硬编数据）

状态 C 下 writer 产出结果章时：

- 允许产出**表/图骨架**（列名、表头、变量清单、模型设定），可用 `<待填>` 占位；
- **严禁填入任何具体数值**——包括看似合理的"示例数字"，因为它们极易被误当作真实结果；
- 交付时必须在正文与台账**双重标注**"⚠️ 结果待数据到位后补"；
- steward 在 `STATUS.md` 将该节状态标为 `待数据`，不得标为 `已过审计`。

> **硬性红线**：任何情况下，正文出现的数据必须能追溯到 `_分析结果_最新.md` 或作者提供的
> 原始输出。**无法追溯的数字一律视为编造。** 这条与"文献不得臆造"同级。

## 二、数据台账（`templates/data-ledger.md` → 项目根 `DATA.md`）

`DATA.md` 是**变量与数据的权威登记表**，地位等同于文献的 `glossary.md`。

### 必录内容

| 栏目 | 说明 | 为什么必须 |
|---|---|---|
| 数据集清单 | 名称、来源、获取方式、样本量、时间跨度、版本/提取日期 | 复现与审稿人质疑时的依据 |
| 变量清单 | 变量名 / 构念 / 测量方式 / 单位 / 取值或编码 / 缺失处理 | 防口径互斥（第三节） |
| 数据可得性状态 | A/B/C/D + 存放路径 | 即第一节的闸门依据 |
| 伦理与合规 | 是否涉人体/隐私数据、是否已获伦理批件、数据可否公开 | 期刊与学位论文均查 |
| 数据处理留痕 | 清洗规则、异常值处理、样本筛除标准 | 审稿人最常追问项 |

### 与 glossary.md 的分工

| | glossary.md | DATA.md |
|---|---|---|
| 管什么 | **术语与概念**口径（文字世界） | **变量与数据**口径（数字世界） |
| 例 | `sleep duration` → "睡眠时长" | 睡眠时长 = 工作日日均小时数（自报，睡眠日记校核） |
| 谁维护 | consistency | analyst（consistency 复核与正文一致性） |

两个台账**交叉引用但职责分离**：glossary 管"叫什么"，DATA 管"怎么量的"。

## 三、分析结果落盘（`_分析结果_最新.md`）

**机制与 `_文献池_最新.md` 完全对称**——这是本流水线已证明有效的模式，此处复用：

```
数据/原始输出（作者提供）
   ↓  analyst 核验、整理
_分析结果_最新.md        ← 唯一权威来源（writer 引数字、auditor 核数字，都读它）
   ↓  writer 引用
正文结果章（数字必须可追溯）
```

### 落盘内容（每条结果一个条目）

- **模型/检验标识**：如 `<模型1>`；
- **因变量 / 自变量 / 控制变量**：与 DATA.md 的变量名严格一致；
- **系数与统计量**：系数、标准误、置信区间、显著性、样本量、拟合指标；
- **软件与版本**：`<软件 版本>`（复现必需）；
- **对应表/图编号**：与正文图表编号一一对应（供 `check-figures.ps1` 交叉核对）。

### 硬性传递协议（与文献池同规则）

委派 writer / auditor 时，**必须让其读到 `_分析结果_最新.md` 或完整内联结果条目**。

> **严禁只给"结论式摘要"**（如"睡眠与成绩呈倒 U 型"）而不给具体统计量——
> 那样 writer 只能凭印象补数字，等于编造。
> **writer 拿不到结果条目时，不得写入任何数值**，须回报主代理索要。

## 四、测量口径一致性校验

变量的测量口径若在正文各处不一致，是审稿人最容易抓、也最伤可信度的硬伤。
本流水线原有的 consistency 只查术语/概念/论点，**不查测量口径**——现补上。

### 三方对照

```
DATA.md 变量登记  ⇄  _分析结果_最新.md  ⇄  正文各处表述（方法章 / 表注 / 结果章 / 摘要）
```

### 检查项与典型事故

| 检查项 | 典型事故 |
|---|---|
| 变量名 | 方法章写"学业表现"，表 3 表头写"学习成绩"（同一变量两个名字） |
| 测量方式 | 方法章说"三科加权指数"，结果章说"平均分" |
| 单位/量纲 | 一处"小时"、一处"分钟" |
| 取值/编码 | 一处"1=男"，一处"1=女" |
| 缺失处理 | 只说"剔除缺失"，未说明剔除标准与剩余样本量 |
| 样本量 | 摘要说 N=3826，表 2 说 N=3712（差 114，未说明原因） |

**执行者**：analyst 登记口径；consistency **新增第五维「测量与数据一致性」**负责比对；
不一致处退回 writer 修正（若属 DATA.md 登记错误，先改台账再改正文）。

**样本量不一致是高频硬伤**：摘要、方法章、每个表注的 N 必须能相互解释。

## 五、图表规格（供 item 3 的图表检查使用）

结果章必然产生表与图。**图表必须在 DATA.md 或结果条目中登记规格**，否则
`check-figures.ps1` 只能发现"正文引用了不存在的表 3"，无法判断表 3 该不该存在。

登记内容：编号 / 类型（表/图）/ 题注 / 是否已在正文引用 / 数据来源（哪条结果条目）。
正文与图表的编号一致性由 `scripts/check-figures.ps1` 机械核验。

## 六、新增角色：analyst（数据分析员）

原七角色无人负责数据。新增 **analyst**，定位与 librarian 对称（一个管文献，一个管数据）。

| 项 | 内容 |
|---|---|
| 职责 | 数据可得性核查、数据清洗留痕、执行或核验分析、结果落盘、图表规格登记、测量口径登记 |
| 硬性规则 | **不得编造数据或结果**；无法执行分析时如实说明并给作者可操作的步骤，不得估算 |
| 不做什么 | 不写正文（那是 writer）、不做论证（那是 planner） |
| 档位建议 | 中强档（需能执行/理解统计分析，且结构化输出稳定） |
| 何时不派 | 状态 D（无实证数据）时整节跳过本角色 |

## 七、流程插入位置（更新后的流水线）

```
第〇步 读 MODE.md + 状态恢复 + 同步进度
   ↓
第〇·五步【新增】数据可得性闸门（状态 A/B/C/D）+ 数据台账核验 + 分析结果落盘
   ↓
第一步 独立规划（planner）—— 实证单元须引用 _分析结果_最新.md 而非凭空规划
   ↓
第二步 执行写作（writer）—— 结果章数值必须可追溯
   ↓
第三步 独立审计（auditor，五维）+ consistency（新增第五维：测量与数据一致性）
   ↓
第四步 文献落库 + 数据/结果留痕
   ↓
第五步 交付（引注三对照 + 篇幅核验 + 图表编号核验）
```

## 八、与其他文件的关系

- 图表编号机械核验：`scripts/check-figures.ps1`（见 item 3 说明）
- 数据台账模板：`templates/data-ledger.md`
- 分析结果模板：`templates/results.md`
- 角色定义：`prompts/roles/analyst.md`
- 术语/变量分工：`templates/glossary.md`（术语）与 `templates/data-ledger.md`（变量）
