# 定制系统提示词（引导 Agent 的作业单：开题报告模式 / 访谈模式）

> 目标：把 `prompts/system-prompt.md`（模板版）定制成**属于你的版本**——直接用于你的论文课题。
> 你不需要手工逐段改写：把下面的作业单连同你的开题报告一起交给 Agent（Codex 或 DeepSeek Harness 均可），
> 让它输出三个文件：项目根 `MODE.md`、定制后的 `prompts/system-prompt.md` 与项目根 `AGENTS.md`。
>
> **没有开题报告？不影响**——见文末「模式二：无开题报告的访谈式定制」，Agent 通过问答即可完成同等定制。

## 适用前提

- 你已有一份**开题报告**（docx / pdf / md 均可），其中包含：研究主题与题目、研究背景与问题意识、
  核心概念与理论工具、论文结构与章节大纲、参考文献方向。
- 你的 Agent 环境已能读写本仓库文件。

## 第 0 步（新增，必做）：先确定写作模式

**模式决定后面所有标准**（篇幅、结构单元、创新性门槛、引注体系、评审口径、台账粒度）。
未确定模式就定制提示词，会导致整条流水线的标准失准。先按 `modes/_mode-overview.md` 的决策树定模式：

```
交给学校/学院评审、有学位授予含义？ → degree-thesis（本 bachelor / 硕 master / 博 doctor）
要投给期刊、有审稿流程？           → journal-article（须确认目标期刊/类型/字数上限/体例）
交给老师、算课程成绩？             → course-paper（须确认课程要求与评分点）
```

**判不准时向用户提二选一问题确认，不得擅自默认。** 确认后，Agent 须生成项目根 `MODE.md`
（模板 `templates/MODE.md`），并**请用户确认一次**（填错模式=标准失准）。

> 期刊论文与课程论文模式**有前置必填项**，缺则不得开工：
> 期刊需 `target_journal` / `article_type` / `word_limit_hard` / 引注体例；
> 课程需 `course_name` / `instructor_requirements` / `grading_rubric`。

## 模式一：开题报告自动定制（有文档时用）

### 作业单（把下面这段原样发给 Agent，替换其中的 <> 为你的信息）

```text
请以本仓库为工作目录，执行「开题报告 → 定制提示词」任务。

## 输入材料
项目根目录下的开题报告文件：<开题报告文件名.docx>（若无法直接读取 docx，
请先用 PowerShell 解出 word/document.xml 转成 markdown 快照再继续）。

## 任务
0. 先确定写作模式：按 modes/_mode-overview.md 的决策树给出 mode 与 level，
   向我确认（一次二选一提问即可）；确认后按 templates/MODE.md 生成项目根 MODE.md。
   若为 journal-article / course-paper，先补齐该模式的必填项（目标期刊/类型/字数上限/体例，
   或课程名/教师要求/评分点）——缺失项须问我，不得自行假设。
1. 通读开题报告，提取：研究主题与题目、核心问题意识（含对既有研究的批判）、
   核心理论/框架及关键机制模型、章节结构大纲、拟用术语清单（含外文术语的选定译名）。
2. 打开 prompts/system-prompt.md（模板版），按开题报告内容执行以下替换：
   - 「研究课题的底层学术画像」整段：按模板括号里的同构句式，改写为开题报告的真实内容
     （既有路径批判 → 待解决的具体问题 → 问题的重要性；1-2 个核心理论/方法工具）；
     **注意：理论/方法工具的形态随学科而变**——文科常为"概念框架+机制模型"，
     理工医常为"数学模型+实验/试验设计"，人文常为"核心范畴+文本/史料分析路径"，
     按该课题所属学科的惯例填写，不要套用其他学科的理论章写法；
   - 「三大核心功能」示例中的章节标题、示例句：换成开题报告大纲里的真实章节；
   - 「术语与一致性审查」中提到的术语示例：换成开题报告的关键术语与译名；
   - 其余流程性内容（第〇步～第五步、角色分工、行为准则）保持不动。
3. 把定制结果写回三个位置：
   - MODE.md（项目根，写作模式配置，模板见 templates/MODE.md）；
   - prompts/system-prompt.md（覆盖为你的定制版）；
   - AGENTS.md（Codex 项目指令：内容与定制版 system-prompt.md 一致，
     作为项目根目录的指令入口——Codex 会自动读取）。
4. 完成后输出一份「定制报告」：列出你做了哪些替换、哪些占位符仍需人工确认
   （如文献库父集合键、模型路由等），以及建议作者人工复核的段落。

## 约束
- 不得改动模板的流水线结构（第〇步～第五步）与七个角色定义；
- 不得把某个学科的理论写法强加给另一学科；
- 涉及用户隐私的信息（真实姓名、院校、导师）在 AGENTS.md 中一律用 <占位符>，
  不要在仓库中写入真实个人信息；
- 完成后不得自行 push，等待作者审阅。
```

## 使用 Codex 执行

```bash
codex "执行 AGENTS.md 定制任务：读取开题报告并生成 MODE.md、prompts/system-prompt.md 与 AGENTS.md，作业单见 docs/customize-from-proposal.md"
```

或将作业单全文粘贴进 `codex` 会话。

## 使用 DeepSeek Harness 执行

把作业单全文粘贴进 DSH 会话即可；DSH 主代理会按提示词协议自动完成读取、改写与写回（docx 转换步骤已内建于作业单第 1 步）。完成后把生成的 `prompts/system-prompt.md` 内容放入项目 `.dsh/prompt.md` 即完成装载（见 README Quickstart 方式 B）。

## 模式二：无开题报告的访谈式定制（无文档时用）

没有开题报告时，**部署不必中断**。由 Agent 主动发起一轮结构化访谈，把对方的回答填入模板，产出与模式一相同的三个文件。访谈控制在 1 轮、约 11 个问题；对方答不上来的项，Agent 给出「基于 demo 示例的占位建议」并标注"⚠️ 待确认"，绝不让定制卡死。

### 作业单（把下面这段原样发给 Agent）

```text
请执行「访谈式定制提示词」任务。用户没有开题报告，请以问答方式收集课题信息。

## 访谈流程
一次只问 1 个问题，等用户回答后再问下一个。全部问完后一次性完成定制，不再追加提问。
若某题用户表示"不知道/你建议"，按 demo 示例课题的写法给出占位建议并标注 ⚠️待确认。

## 必问问题（按序）
1. 这份要写的东西，是交学校评审的（学位论文）、投期刊的、还是交课程的？
   （决定写作模式：degree-thesis / journal-article / course-paper）
2. 若是学位论文：本科、硕士还是博士？（决定档位与创新性门槛）
   若是期刊论文：目标期刊是哪本？稿件类型（原创研究/综述/案例/方法/书评）？
   字数上限多少？引注体例是序号制还是著者-年制？
   若是课程论文：课程名是什么？老师的要求原文（篇幅/引注/格式/截止时间）？
   课程大纲里有没有评分点？
3. 论文的研究主题/题目是什么？（一句话；暂无则问学科领域 + 大致方向）
4. 所属学科（如：教育学/计算机科学/材料科学/社会学/历史学……）？
   ——用于确定术语体系与文献分布，不预设任何学科。
5. 你批判既有研究停留在什么层面？想攻克的"具体机制/核心问题"是什么？
   （提示句式：既有路径批判 → 待解决的具体问题 → 该问题为何重要）
6. 计划使用哪 1-2 个核心理论/分析框架或核心方法路线？（无则说明你的研究路径）
7. 是否有一个刻画动态过程的机制模型（闭环/循环/递归类）或关键分析模型？
   没有可由 Agent 按领域常识建议。
8. 文章大致分几章/几部分？各章主题（哪怕很粗略）？
9. 3-5 个关键术语及其外文原文（用于 glossary 译名登记；中文术语则说明其英文对应）。
10. 写作语言（中文/英文）与目标篇幅？
11. 是否已确定稿件主文件名（docx）？在哪个路径？
    其他需要 Agent 知道的偏好（称呼、文献库偏好、引用风格等）。

## 定制动作（访谈结束后执行）
按模式一的「任务」第 0、2、3、4 步执行：生成 MODE.md、改写 prompts/system-prompt.md 的
底层画像与示例段落、生成 AGENTS.md、输出定制报告（列出替换项 + ⚠️待确认项）。

## 约束
同模式一：不改流水线结构与角色定义；不把某学科的理论写法强加给另一学科；
用户真实身份信息一律用 <占位符>；完成后不自行 push，等待作者审阅。
```

### 如果用户连访谈都不愿参与（最坏情形）

仍有第三级兜底：**先用 demo 虚构课题完成部署**（README 自动部署协议照常跑通阶段 1-6，冒烟测试用 demo 数据——**按拟用模式选对应那套 demo**：`demo/degree-thesis/`、`demo/journal-article/`、`demo/course-paper/`），整条流水线先验证可用；待用户日后提供课题信息时，重跑本文件的模式一或模式二即可"换肤"，无需重新部署。

## 人工复核清单（Agent 输出后必做）

- [ ] **`MODE.md` 的 mode 与 level 是否正确**（模式填错＝后续所有标准失准，最优先核对）；
- [ ] 期刊论文模式：目标期刊、稿件类型、字数硬上限、引注体例是否已确认；
- [ ] 课程论文模式：课程要求与评分点是否已逐条抄入；
- [ ] 底层学术画像是否准确反映你的问题意识（不是套话）；
- [ ] 理论工具与机制模型是否与开题报告一致，且**形态符合本学科惯例**；
- [ ] 大纲章节编号是否与你的最新目录一致；
- [ ] 占位符是否已全部处理或标注"待确认"；
- [ ] AGENTS.md 中无真实姓名/院校/导师信息。
